A workbench, not a widget

Thirty focused tools across five areas, sharing one engine and one job queue.

PDF workstation

Merge, split, extract, reorder, rotate and clean PDFs. Compress embedded images, edit metadata, watermark documents and build PDFs from images.

Documents

Create and convert DOCX through the native OOXML engine. Markdown, plain text and HTML to PDF with system font embedding.

Spreadsheets & CSV

A real CSV workbench: delimiter and encoding detection, type inference, filtering, sorting, deduplication, splitting, joining, CSV ↔ XLSX ↔ JSON.

Image Lab

Convert between PNG, JPEG, WebP, BMP, TIFF and AVIF. Resize, crop, rotate, strip metadata, render SVG, trace raster to vector, build ICO icons.

Conversion center

One route from input to output with an honest capability registry. Unsupported conversions stay disabled instead of failing silently.

Job runtime

Every operation runs as a cancellable job with staged progress, bounded concurrency, atomic writes and verified output.

Supported formats

PDF

Open, inspect, merge, split, extract, delete, reorder, rotate, compress, watermark, metadata, privacy clean, images to PDF.

Documents

DOCX, Markdown, TXT, HTML, RTF inspection. Legacy DOC through the optional LibreOffice adapter.

Spreadsheets

CSV, TSV, XLSX, XLS and ODS reading; XLSX writing; CSV ↔ XLSX ↔ JSON conversion.

Images

PNG, JPEG, WebP, BMP, TIFF, AVIF, GIF, SVG, ICO. SVG rasterization and vector tracing for logos and line art.

Your files stay on your machine

No upload

Processing happens in the local native core. There is no server component and no account.

No telemetry

No analytics, no crash reporting, no tracking. Logs contain operation metadata only, never document contents.

Safe writes

Outputs are written to a temporary file, flushed, verified and only then moved into place. Source files are never overwritten by default.

Honest limits

No “lossless 90% compression” promises. PDF rendering to images requires the optional PDFium adapter, and the UI says so.

Scriptable from day one

The same engine that powers the app is available as a command line tool with JSON output and clean exit codes.

tdx-doc pdf split file.pdf --chunk 25 --out-dir out/

tdx-doc image trace logo.png -o logo.svg --preset poster

FAQ

Does anything get uploaded?

No. All processing happens locally in the native Rust core. The application has no server component and requires no account.

How is this different from online converters?

Speed, privacy and reliability. There are no queues, no file size limits imposed by someone else's server, and no documents sitting in a temporary cloud folder.

Which licenses do the dependencies use?

The core targets permissive licenses only (MIT, Apache-2.0, BSD, ISC, Zlib, MPL-2.0). LibreOffice and PDFium are optional external adapters, never bundled, and are documented in THIRD_PARTY_LICENSES.md.

Can I use it in scripts and CI?

Yes. tdx-doc returns stable exit codes, supports --json everywhere and works without any GUI. See docs/cli.md.
